# Focus, visibility, animation and performance source changes

Source-only update: no compilation, linking, game launch, DLL copy or config-file change was performed in this pass, as requested. Build and runtime validation remain for the user. Previously generated DLLs in build/ and outputs/ do not include these changes.

Changes:
- WindowFocusPolicy filters WM_KILLFOCUS, inactive WM_ACTIVATE and false WM_ACTIVATEAPP before calling the game WndProc. Windows default processing and ImGui focus processing still run. The mapped native WndProc 1073E30 sets its internal inactive flag on WM_KILLFOCUS. This targets automatic tab-away pause; it does not disable deliberate Esc/inventory/cutscene pause logic. Background frames release cursor confinement. F1 only toggles the focused instance.
- Skip overlay frame generation and draw calls when the menu is closed. Explicitly preserve and restore all OM render/depth targets around menu rendering, rather than leaving the game's graphics context bound to the overlay backbuffer. DXGI_PRESENT_TEST calls no longer run mod updates.
- Only invoke the full native position/rotation update when the live transform differs from the target. Quaternion sign equivalence is respected. Publish changed transforms into C7 with the corrected one-stack-argument F3DBD0 wrapper, instead of relying entirely on the ordinary component update pass.
- Create proxies and apply appearance before motion replay, preventing same-frame appearance replacement from discarding freshly queued animation. Briefly defer events until a valid appearance/controller exists, with a bounded 128-event queue, six replay attempts per frame and 750 ms expiry measured on the receiver's clock. Events from previous worlds are cleared. This remains event replication; it does not implement full animation playhead/late-join pose synchronization.
- Avoid copying already-applied visual blobs on every frame. Sample native metadata at 30 Hz. Remove routine per-line FlushFileBuffers and console writes while the console is hidden; errors and shutdown retain flushing. Respect ConsoleOnStartup.
- Add [Performance] ForegroundFPS=60 and BackgroundFPS=30 defaults in source configuration. Each can be set to 0 to disable that cap. These are caps, not promised minimum frame rates. No existing configuration file was edited. Both instances remain running; the background instance gets a smaller rendering budget.
- Add five-second mod-work average/peak timings (excluding intentional pacing and driver Present waits) and motion sent/received/replayed/dropped counters, so a new test can distinguish mod work from engine/GPU/Sandboxie contention.
